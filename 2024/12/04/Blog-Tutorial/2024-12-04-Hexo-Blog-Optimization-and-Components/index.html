一些前言

想来想去，还是要完成博客的最终设计，使得博客功能尽可能完善，至少让他看起来是安全且美观的一个小网站，因此本文梳理了Hexo-Fluid主题的一些基本修改思路，并给出了一些组件使用的方案，还实现了HTTPS的升级，中间附带一些稀奇古怪的思考和教学，希望你看得开心，也希望对于有需要的朋友能产生一些帮助。

内容一：博客美化

对于Material Design风格的Fluid主题，自身功能已经很完备了，且界面也比较好看，因此这里也不过多介绍。首先博客的基础美化和基础信息设置大家参考官方手册即可，或者直接看_config.fluid.yml文件里的注释也基本能看明白，大体来说，设置文件分为几部分：

  • 全局Global设置，这块主要更改浏览器标签图标，这里可以参考Fluid官方提供的icon包，也可以用iconfont-阿里巴巴矢量图标库里面的图标，其次一个比较重要的设置是强制所有链接升级为HTTPS，可以改成true。其他的例如标题打字机等这些特效设置，参考注释和文档自行修改即可。
  • 页头Header设置，这块主要是导航栏部分的设置，例如导航栏左上角的站名，以及导航栏功能设置等，和搜索功能设置，以及网页视觉效果的一些设计。
  • 页脚Footer设置，对于国内网页来说，重点是备案号的设置，其余的包括可以设置一些文字，也可以加上网站浏览量显示等功能。
  • 首页Home Page设置、文章页Post Page等等页面设置，查看注释自行按照需求更改即可。这块都没有什么技术难点，也就不做分享了。

这里只分享一些需要其他配置的美化思路，由于已经有很多成熟方案了，这里就分享几个我觉着不错的教程，跟着教程来按需修改即可：

题外话一：什么是反向代理？
反向代理是一种服务器配置，通过它，客户端的请求一般先发送到反向代理服务器，然后该服务器将请求转发到后端实际服务器（目标服务器），反向代理服务器在用户和目标服务器之间充当中介，处理请求和响应。反向代理服务器有助于负载均衡、安全性提示、简化后端等。反向代理和正向代理的区别就在于，反向代理是用户向反向代理服务器发送请求，反向代理代表用户向内部服务器发送请求。而正向代理则是用户通过代理服务器访问互联网，代理服务器代表用户向外部服务器发送请求（这就是常说的梯子）。

题外话二：域名的构成，域名解析的概念，以及CNAME的概念
域名级数是指一个域名由多少级组成，域名的各个级别被.分开，最右边的那个词称为顶级域名。顶级域名，又被称为域名后缀，常见的有.com、.org、.net、.cn等，也存在带两个层级的域名后缀，例如：.com.cn、.org.cn、.net.cn等。

  • “一级域名”就是在顶级域名前再加一级，一级域名也被称为根域名，例如：”aliyundoc.com”、”aliyundoc.com.cn”。
  • “二级域名”就是在一级域名前再加一级，例如：”example.aliyundoc.com”、”example.aliyundoc.com.cn”。
  • “三级域名”就是在二级域名前再加一级，例如：”www.example.aliyundoc.com"、"www.example.aliyundoc.com.cn"。
    所谓的域名解析就是用户在浏览器中输入一个域名时，浏览器会向DNS服务器查询该域名的IP地址，一般查询从根服务器开始，指向顶级域名的TLD服务器，TLD服务器再向指向该域名的权威服务器，最后由权威服务器找到域名的A记录，返回相应IP地址给最初的DNS服务器。其中域名解析包括：A记录（域名映射到IPv4地址）、AAAA记录（域名映射到IPv6地址）、CNAME记录（将一个域名指向另一个域名）、MX记录、NS记录、TXT记录。
    了解了这些概念后，CNAME（Canonical Name Record）就是一种 DNS（域名系统）记录类型，用于将一个域名别名映射到另一个域名的真实（规范）名称。通过使用 CNAME 记录，可以将多个域名指向同一个 IP 地址或服务，方便管理和提高灵活性。CNAME记录不能与其他记录同时存在于一个域名下，这就保证了域名解析在DNS中的唯一性，即CNMAE记录是DNS服务中的一种映射，不会对域名本身占用。

内容三：网站优化

一、SSL证书(HTTP升级到HTTPS)

网站升级到HTTPS（超文本传输安全协议）是提升网站安全性和用户信任度的重要步骤，HTTPS使用SSL/TLS协议对传输数据进行加密，保护用户和服务器之间的信息不被窃听或者篡改，其中SSL/TLS证书可以验证网站真实性，确保用户访问的是合法和安全的网站。且一些搜索引擎，例如Google更倾向于排名HTTPS网站，也就是常说的SEO优势。

题外话：到底什么是SSL/TLS
简单来说SSL（安全套接字层）和TLS（传输层安全性）是用于加密互联网通信的协议，TLS属于是SSL的后续版本。这个过程一般包括几个步骤：1. 握手过程：浏览器和服务器进行初步通信，协商使用的加密算法和密钥；2. 身份验证：服务器向浏览器提供其SSL/TLS证书，浏览器验证证书真实性，查看证书是否由受信任的证书颁发机构签发；3. 生成会话密钥：基于协商的算法，浏览器和服务器生成一个会话密钥，加密后续数据传输；4. 加密通信：所有通过该链接传输的数据都使用会话密钥加密。 此外该协议还可提供数据完整性校验。

回到正题，哪里可以搞到SSL证书呢？ 既然是个人网站，那么优先追求的就是高质量且免费，有很多受信任机构可供选择，比如一些云服务供应商AWS、Google Cloud、Azure等，这里博主选择CloudFlare来进行域名解析以及后续的免费SSL证书申请。

由于我的域名在之前作网站测试的时候以及在阿里云解析过了，因此这里要先到阿里云把DNS服务器修改到CloudFlare，具体操作流程为：

  1. 进入Cloudflare网站，创建并登陆账户。
  2. 在Websites选项卡中点击添加站点Add a domain。
  3. 输入你之前购买的域名（例如 example.com）并点击添加站点。
  4. 选择免费计划即可。
  5. 然后Cloudflare会自动扫描该域名的DNS记录。同时下滑页面会发现Cloudflare会提供两个名称服务器（如ns1.cloudflare.com和ns2.cloudflare.com），记录这两个服务器名称。
  6. 登录阿里云控制台。
  7. 选择域名列表找到要更改DNS服务器的域名，点击管理按钮，找到DNS管理下的DNS修改部分，然后修改服务器为Cloudflare提供的两个名称服务器。

    以上过程比较简单，然后需要在Cloudflare部分等待一段时间，直到DNS服务生效。

待DNS服务激活后，到SSL/TLS界面进行配置即可，一般Flexible模式即可，且要记着到Optimization中Enable Always use HTTPS。


同时最好开下Automatic HTTPS Rewrites，防止网站内部有些资源是http资源，而导致内部链接重定向失败的问题。

这些都是CloudFlare中的设置，但这时你会发现你的网站如果不能通过https打开，则说明你需要在服务器安全组中开放443端口，如果可以正常打开，那么你会发现网站依然可以通过http访问，也就是说http和https都可以访问网站，那怎么能行。所以还需要在服务器上做一些Nginx的配置。

其中证书以及私钥从CloudFlare中下载，在SSL/TLS下的Origin Server中，创建一个即可，然后分别将源证书中的内容和私钥的内容复制到txt文件中，源证书文件后缀修改为.crt，私钥文件后缀修改为.key，然后保存在上述推荐路径下即可。进行到这一步，需要执行以下命令，重启Nginx Web服务，并重新生成网页内容，这里同时建议将CloudFlare中的模式暂时切换为开发模式，且清除浏览器对网站的缓存，然后重新上线。

进行到这一步，到浏览器中测试网站发现已经能够自动跳转到https了，大功告成。 不过这里要说明下，因为Cloudflare DNS服务器都在国外，所以改用这里的DNS服务器在一定程度上会导致国内访问速度变慢，但好处是有更好的安全保证，有免费的SSL支持，这就是一种权衡，关键看你选择。

二、网站CDN加速

在# Github+PicGo+Obsidian——一套完整好用的图床技术链（+网站上线）一文中，博主已经介绍了什么是CDN，简单来说，CDN利用最靠近每位客户的服务器，将文件更快的发送给用户，从而提升站点（尤其是包含大量图片或静态网页的站点）的访问速度。

那么如何利用CDN加速服务，提升自己的网站访问速度呢？这里依旧带来的是基于CloudFlare的实现方案。首先这里再说明下，对于国内网站来说，非必要其实不需要使用CloudFlare的CDN，因为CloudFlare服务器都在海外，这样反而会降低国内对于该网站的访问速度，但我们却想要使用CloudFlare带来的IP隐藏以及SSL证书服务，那只能说这是一种权衡，当然基于CloudFlare的CDN服务，我们的网站在国外有了不错的访问速度，也算是不错的结果。

对于如何自定义IP路由，优化国内访问速度，网上已有方案，基于梦牛网络 Cloudflare全球合作伙伴 CF高防御CDN 外贸首选 (mnn.tw)实现的。

三、图片自动压缩成webp格式

最后一个优化则是对图片进行压缩，其实无论对于将图片存储在网站服务器上，或者使用在线图床来实现图片在线加载，对图片做压缩都是有好处的，能够一定程度上加快博客加载的速度，节省大量带宽，也可以一定程度防止盗图。

目前的方案一是使用WebP Server Go，在博客所在服务器上搭建一个服务，用于在线监听上传到博客的图片，并执行格式转换和压缩等。为网站添加图片 WebP 自动转换功能 - 知乎 (zhihu.com)
方案二是使用Pillow处理图片格式转换以及水印，然后使用Git hook功能实现自动推送，参考：我是如何使用 Git 和服务器做图床，并使用 hook 实现 WebP 压缩与水印的？-CSDN博客。这块技术还需要再研究研究，若后续实现会再出一期博客。

小结

对于一个博客网站来说，以上功能都设置好后也就差不多了，对于博主来说，一方面我是想简单折腾折腾，顺便学习或复习下关于Web以及网络的一些知识，此外我将博客当作分享日常生活或学习记录的一个工具，折腾到最后也许你也会发现，文字才是博客的灵魂。我希望自己不是三分钟热度，而是真正想用这个博客给自己带来一些真正向上的动力，你我共勉。最后附上一个使用该主题写博客的基础教程，包括Markdown一些特殊用法，以及插图网站：搭配fluid如何优雅的写一篇文章。
