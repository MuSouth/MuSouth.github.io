一些前言

大概等了四天左右，本站的域名备案完成，也就说明网站可以正式上线了，前文《在阿里云服务器上搭建Hexo(Fluid主题)博客——完整流程》我们讲过使用域名以及网站上线和在本地或者服务器上测试部署还是有些差异的，因此本篇博客主要分享如何开放公共网络访问。并顺便分享了如何DIY自己的在线图床，从而节省服务器本地存储图片的空间（最新测试可以使用）。

一、网站上线的原理

作为一个静态博客网站，网站上线的核心原理在于将开发好的静态文件（例如HTML、CSS、JavaScript等）放置在服务器上，并通过Web服务器（例如Nginx和Apache）将这些文件提供给访问者，整个过程主要分为以下几步：

  • 域名解析：用户在浏览器输入域名时，DNS 服务器将域名解析为服务器的 IP 地址。
  • 请求处理：用户的浏览器向 Web 服务器发送 HTTP 请求，请求特定的文件（如网页）。
  • 文件响应：Web 服务器接收到请求后，根据请求的 URL 找到相应的文件，并将其发送回用户的浏览器。
  • 页面渲染：用户的浏览器接收到文件后进行解析和渲染，最终展示给用户。
    这时不熟悉Web技术的同学们可能产生了疑问，那我之前按照你的教程只安装了Node.js以及Hexo，为什么开放特定端口（例如hexo server -p 8080）后可以访问，但我直接开放端口80（PS:端口80是广泛使用的基本默认的网站开放端口，一般情况下网址链接上都会省略不写，但实际访问的就是80端口）为什么不能访问网站呢？其实这是因为Hexo自带一个内置的用于开发测试的Node.js服务器，它会监听本地请求，通常是默认的localhost:4000地址（也可以通过访问http://你的服务器IP:4000来访问），当然这个4000可以根据你的需求去更改，但一定要记得到服务器防火墙安全组处开放对应端口。

看到这里你应该大概明白了，尽管我的服务器已经默认开放了80端口，且域名备案完成了，但是我缺少一个Web服务器来负责文件处理和反向代理请求，因此本文将教会你如何使用和设置Nginx以正式开放网站。

然后你需要开放Nginx用户www-data对你博客目录下public文件夹的读取权限，这里至少需要755（这里简单说明下Linux系统下文件权限的问题，在Linux中文件权限分为八级，以二进制类似的形式排列组合了读r/写w/执行x三种权限，且对于每个文件的权限分为三个组，所有者Owner、用户组Group、其他用户Others，不同的权限可以用对应的排列组合样式表示，同时可以按照二进制的计算原则转换成十进制数字，从而对应每一个排列，例如只读是r--，换算成十进制就是4，只写是-w-，换算成十进制就是2，同样可执行权限--x则对应1，如果该文件具有所有权限则表示为rwx，对应数字7，如果配置一个文件的权限要同时按照所有者/用户组/其他的顺序，赋予三个组权限，例如我提到的755就是分别赋予所有者、用户组、其他以可读写执行、可读可执行、可读可执行的权限，查看文件或目录权限使用ls -l filename，更改权限则使用chmod 755 filename详细的可以参考这篇博客：Linux文件权限详解）。

言归正传，当然如果发现只给了public目录权限后依旧403，那么就将其父目录同时提升权限，确保顺利访问到public目录即可。

当然这里同时有个馊点子，你注意到了上图中nginx.conf的user选项，如果你将其直接更改为root那么就不需要再授予其权限了，但同时这样做风险很大，例如一旦受到利用Nginx漏洞发起的攻击，网络攻击者就能够获得你系统的root权限，本着”最小权限原则“，我们只需要赋予Nginx访问网站静态文件和进行基本的网络操作的权限即可。

三、Github+PicGo+Obsidian=一款好用且方便图像管理存储的Markdown编辑器

在现代写作和创作中，图片的使用变得越来越普遍。为了方便管理和存储这些图片，许多创作者选择搭建自己的图床。本文将详细介绍如何使用 Github、PicGo 和 Obsidian 打造一个高效的个人图床系统。

1. 所需工具

  • Github：用于存储和管理图片的云端仓库
  • PicGo：一款开源的图床助手，支持多种图床服务
  • Obsidian：一款强大的笔记软件，支持Markdown格式文档

2. Github图床基本原理

Github （或者考虑使用Gitee，但是经博主测试，Gitee应该是加装了防盗链，可能早就禁止使用于图床了）可以用作图床，原理是将图片上传至 Github 仓库，然后在博客中使用 URL 链接来访问这些图片。而通过 PicGo+Obsidian，我们可以在编辑Markdown过程中顺手复制粘贴一张图片，即可轻松上传图片至Github仓库，并自动生成对应的URL链接，方便同时在本地 Obsidian以及服务器博客中进行管理。

  • 填写基本的仓库信息，包括Repo仓库名，分支就用默认的main就好，然后可以添加一个Readme。

    题外话：什么是CDN？
    这类CDN即内容分发网络概念性来说就是一种通过分布在全球各地的边缘节点来缓存和分发内容的技术，CDN 由多个分布在不同地理位置的服务器组成，这些服务器称为边缘节点。这些节点存储和缓存来自源服务器的静态内容。分布式网络：当用户请求某个资源时，CDN 会根据用户的地理位置选择离用户最近的边缘节点。内容缓存：边缘节点会检查是否已经缓存了该内容。如果缓存中存在该资源，CDN 将直接从边缘节点提供资源，从而提高访问速度。回源策略：如果请求的资源不在边缘节点的缓存中，CDN 会将请求转发到源服务器。源服务器响应请求后，CDN 会将该内容缓存到边缘节点，以便后续请求能够更快地响应。负载均衡：CDN 通过智能算法进行负载均衡，将用户的请求分配到不同的边缘节点，这不仅提高了访问速度，还能有效减少源服务器的压力。自动化和优化：CDN 提供自动化的管理和优化功能，包括内容更新、缓存失效策略、压缩、代码优化等。这些功能可以帮助开发者更好地管理资源并提升性能。以jsDelivr为例，其工作流程大致可以总结为：

    • 文件上传：开发者将静态资源（例如 JavaScript 库）上传到 GitHub、npm 或其他源。
    • 请求处理：当用户在网页中引用 jsDelivr 的 CDN 链接时，用户的浏览器向 jsDelivr 的边缘节点发送请求。
    • 缓存检查：边缘节点检查缓存是否有用户请求的文件。如果有，直接返回缓存的文件。
    • 回源请求：如果缓存中没有请求的文件，边缘节点会向原始源（如 GitHub 或 npm）请求该文件。
    • 内容交付：获取到资源后，边缘节点将其缓存并返回给用户。之后，任何后续请求都将直接从缓存中响应。

    我们回到正题，配置好PicGo后，记得最后一步，将其设置为默认图床！

四、小结

这篇博客进行到这里已经基本完成了，但这里要注意两点，一是注意Github单个仓库的容量限制，大概在500MB到1GB吧，超出容量限制要尽快创建一个新仓库用来存储了，并且每个Github用户的总容量是有限制的，不过用于个人博客的一些图片的存储还是足够的，如果不够就另寻他法咯，比如使用阿里云OSS、Amazon S3等数据存储服务，这就是另外的价钱了。此外，自建图床有几点劣势，最显著的特点就是数据隐私性差，且缺乏一些内容优化工具，例如自动压缩、缓存管理、格式支持等，当然这些功能我们依旧可以自己设计，我将会放在后续博客慢慢介绍。这篇博客主要介绍了网站上线和图床搭建两个环节，如果能帮助到你，那我觉得太棒了。
